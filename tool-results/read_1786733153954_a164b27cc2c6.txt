   105→   105→

  1375→  1375→# 31. DOCUMENT EDITING CONFLICT POLICY
  1376→  1376→

  1378→  1378→

  1382→  1382→
  1383→  1383→```text
  1384→  1384→Generate
  1385→  1385→    ↓
  1386→  1386→Working copy
  1387→  1387→    ↓
  1388→  1388→User edits
  1389→  1389→    ↓
  1390→  1390→Detect differences
  1391→  1391→    ↓
  1392→  1392→Review / Reconcile
  1393→  1393→    ↓
  1394→  1394→Adopt selected changes
  1395→  1395→    ↓
  1396→  1396→Update canonical domain model
  1397→  1397→```
  1398→  1398→
  1399→  1399→Financially meaningful changes must require explicit reconciliation.
  1400→  1400→
  1401→  1401→Formatting-only changes should remain presentation-owned.
  1402→  1402→

  1454→  1454→# 34. META-SOP: CREATING A NEW SOP
  1455→  1455→
  1456→  1456→Implement the process for creating a new work definition as data-driven workflow.
  1457→  1457→
  1458→  1458→Default workflow:
  1459→  1459→
  1460→  1460→```text
  1461→  1461→1. Detect knowledge gap
  1462→  1462→2. Gather evidence
  1463→  1463→3. Find similar known work
  1464→  1464→4. Draft WorkDefinition
  1465→  1465→5. Capture cost recipe
  1466→  1466→6. Capture productivity
  1467→  1467→7. Capture execution method
  1468→  1468→8. Capture hazards
  1469→  1469→9. Capture controls
  1470→  1470→10. Capture QA
  1471→  1471→11. Capture PPE / permits
  1472→  1472→12. Capture subcontract treatment
  1473→  1473→13. Validate
  1474→  1474→14. Review
  1475→  1475→15. Approve
  1476→  1476→16. Publish version
  1477→  1477→17. Calibrate after actual work
  1478→  1478→```
  1479→  1479→
  1480→  1480→The workflow itself should be configurable later.
  1481→  1481→
  1482→  1482→The system should be able to say:
  1483→  1483→
  1484→  1484→> "This estimate contains a work item that has no approved WorkDefinition. Create one?"
  1485→  1485→
  1486→  1486→and guide the estimator through the workflow.

  1526→  1526→
  1527→  1527→```text

  1529→  1529→vs
  1530→  1530→actual cost

  1622→  1622→# 38. DATABASE — NEON POSTGRESQL
  1623→  1623→

  1625→  1625→
  1626→  1626→Do not use SQLite as the authoritative source of truth.
  1627→  1627→
  1628→  1628→The target architecture is:
  1629→  1629→
  1630→  1630→```text

  1632→  1632→  ↓

  1634→  1634→  ↓

  1644→  1644→# 39. DATABASE PRINCIPLES
  1645→  1645→
  1646→  1646→Design the database for multi-user and multi-organization use from day one.
  1647→  1647→
  1648→  1648→Major entities should carry:
  1649→  1649→
  1650→  1650→```text

  1655→  1655→created_at
  1656→  1656→updated_at
  1657→  1657→```
  1658→  1658→
  1659→  1659→Where appropriate also support:
  1660→  1660→
  1661→  1661→```text
  1662→  1662→version
  1663→  1663→revision
  1664→  1664→status
  1665→  1665→```
  1666→  1666→
  1667→  1667→Use relational integrity.
  1668→  1668→
  1669→  1669→Use foreign keys.
  1670→  1670→
  1671→  1671→Use database transactions for commercially important operations.
  1672→  1672→
  1673→  1673→Do not put the canonical business state in JSON blobs merely because they are convenient.
  1674→  1674→
